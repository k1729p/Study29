In Java 25 project Study29 I am implementing Java database clients to databases in Docker containers.
Goal of these clients is to have base for query research using modern, professional Java database client.
These clients run only on local Windows 10 machine.
For this research project there are no plans for deployment on Cloud, deployment to production, or implementing tests.
Because my other, more complicated, projects are based on Spring Data with Hibernate or on Quarkus Panache,
these libraries should be not used here (because queries are not complicated here).

Please act as a professional Java 25 Developer.
For Elasticsearch database please implement class 'kp.clients.elasticsearch.ElasticsearchDatabaseClient'
with entry method 'public static void process(String key)'.
For connection to database in Docker container please use these  configuration parameters:
```
ELASTICSEARCH_HOST=localhost
ELASTICSEARCH_PORT=9200
```
Docker container is using image 'elasticsearch:9.3.2'.

As a template you could use attached PostgreSqlClient class.
I know it was good template for other relational databases like Oracle, and this is not relational database.

Use relevant professional solutions,
like for example try-with-resources statement or streams with Optional::ofNullable.
If it is possible for this database, please add Schema Discovery Queries.
Create database pool for this connection if you find it reasonable.
Besides,  if it happens, that you use Hikari, please add 'config.setDriverClassName'.
Please list Maven dependencies required by this client, which I will add to 'pom.xml'.
The tables 'departments' and 'employees' already exists in target database.

I have added for your information files from other project, which uses Typescript and Node.js and
queries those 'departments' and 'employees' tables.
These are the files elasticsearch.constants.ts and elasticsearch.department.repository.ts.
That Typescript project works as expected with this Elasticsearch database in Docker container.
